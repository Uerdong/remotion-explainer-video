## 1. 原则：只换皮不动骨头

用户拿一张新封面说"按这个再优化一版"，要的是**同一支片子换个气质**，不是重做。

- 保留：配音、BGM、音效钉帧、段落边界、字幕全文、总帧数。
- 只改：`theme.ts` 的色值、组件的外观属性、个别场景的背景光/描边/字体。
- 结果：新成片与旧成片**帧级对齐**，时长完全一致，可以直接替换或 A/B。
- **旧文件一个字节不动**，新文件另起名（如 `<name>-v2-cinematic.mp4`），并在交付说明里加一节对照表。

判断是否越界：如果一个改动会让某段时长变化、或让某句字幕改字，说明已经超出"换皮"，要先问用户。

## 2. 什么时候该换肤、什么时候该重做

| 信号 | 做法 |
|---|---|
| 新封面/新 VI 与原片语言同构（同样扁平、同样信息结构） | 换肤，1 次渲染 |
| 结构语言也变了（如从"图表演示"变成"实拍叙事"） | 重做分镜，不复用时间轴 |
| 只是想要更"高级/电影感" | 换肤 + 叠层，不加镜头 |

## 3. token 映射表

白底扁平 → 暗色电影感（键名不变，只换值）：

| token | 原值 | 新值 | 作用 |
|---|---|---|---|
| `bg` | `#FFFFFF` | `#070B14` | 主底，近黑的深蓝 |
| `accent` | `#1677ff` | `#D8A455` | 主强调由蓝转金 |
| `ink` | `#444444` | `#E8EEF7` | 正文提亮，深底可读 |
| `inkMid` | `#7A8699` | `#93A4BA` | 次级文字 |
| `line` | `#DCE6F2` | `#33465F` | 细线 |
| `panel` | `#EAF2FF` | `#0E1726` | 卡片/标签底 |
| `pop` | `#EAF2FF` | `#182234` | 高亮底 |
| `bad` | 无 | `#E2453C` | 背叛/双输 |
| `good` | 无 | `#2FBF71` | 合作/双赢 |

再追加剪影专用：`figureA`（冷蓝）、`figureB`（冷灰）、`figureFaded`（褪色）、`rim`（轮廓光色）。

## 4. 五个视觉升级点

1. **轮廓光**：深底上扁平人物会糊成一团。给身体与头部加 `stroke`，宽 2–2.5px、`strokeOpacity 0.5–0.6`、冷色（如 `#8FB4D8`），轮廓立刻"立"起来。
2. **双色对峙光**：在主体左右各放一团 `radial-gradient` 的绿/红光，强度由剧情变量驱动（背叛那拍绿熄红升）。这是最便宜也最有效的"电影感"。
3. **渐变衬线大标题**：`linear-gradient(100deg,#FFFFFF 0%,#F7E8C6 36%,#E5B65E 64%,#A2782A 100%)` + `WebkitBackgroundClip:'text'` + `filter: drop-shadow(0 0 34px rgba(216,164,85,.28))`，字体用 `FONT_SERIF`。字号可放大 10–20%，衬线比无衬线更耐放大。
4. **玻璃字幕条**：底 `rgba(6,10,18,0.82)`、1px 金色描边 `rgba(216,164,85,0.26)`、左侧 6px 金色竖条，取代白底高不透明条。
5. **结局语义转色**：结论、双输、惩罚类标签由主强调色改为红色，与"合作侧绿"形成语义对立。

## 5. CinemaOverlay 实现

插在画面之上、字幕之下，三件事叠加：

```tsx
// 1) 暗角
background: 'radial-gradient(ellipse at 50% 46%, rgba(0,0,0,0) 44%, rgba(0,0,0,0.52) 100%)'
// 2) 胶片颗粒：SVG feTurbulence，位移由帧号推导保证确定性
<feTurbulence baseFrequency={0.8} numOctaves={3} seed={11} />
// transform: `translate(${(frame % 13) * 3}px, ${(frame % 11) * 3}px)`
// opacity 0.07, mixBlendMode: 'screen'
// 3) 上下压暗
background: 'linear-gradient(180deg, rgba(4,8,14,0.60) 0%, transparent 16%, transparent 74%, rgba(4,8,14,0.66) 100%)'
```

颗粒必须用帧号取模位移，不能用随机；否则每帧噪点不同，压缩率暴跌且不可复现。

## 6. 验证与体积

验证：六段各出一张静帧，检查字幕可读性、人物是否糊、金色高亮是否压过正文、标题是否被裁。

体积：颗粒会把码率拉高数倍（示例 5.2MB → 43.2MB）。可选的降体积手段按效果排序：

1. 颗粒 `opacity` 0.07 → 0.03（视觉几乎不变，体积明显下降）
2. `numOctaves` 3 → 1
3. 直接去掉颗粒，只留暗角与压暗

体积问题要向用户说明原因，并给出"要不要砍颗粒压体积"的选项，不要擅自重渲覆盖。
